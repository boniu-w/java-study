IcdaSessionManager锁机制：

1. **悲观锁 (Pessimistic Locking)**：
   - 假设冲突会发生，在操作前先获取锁
   - 代码中通过 `tryAcquireLock` 获取锁，通过 `releaseLock` 释放锁
   - 如果锁存在且未过期，直接返回失败，不允许并发

2. **乐观锁 (Optimistic Locking)**：
   - 假设冲突很少发生，不加锁，但在更新时检查版本号
   - 使用版本号或时间戳来检测冲突

在这个场景中选择悲观锁的原因：

1. **计算密集型操作**：ICDA 评估是复杂的计算任务，可能耗时较长（10分钟超时），如果两个用户同时触发计算，会造成资源浪费

2. **独占资源**：历史评估计算可能涉及大量内存和 CPU 资源，不适合并发执行

3. **业务逻辑要求**：一个用户同时只能有一个计算任务在进行中（`hasComputingSession` 方法），这是业务需求而非性能优化

4. **数据一致性**：计算过程中涉及多个步骤和中间状态，如果允许并发可能导致数据不一致


5. **会话隔离性**：Redis 中的会话状态需要确保每个用户的计算流程完整且不被打断

悲观锁通过提前阻止并发请求来保护共享资源，而乐观锁则是在冲突发生时才处理。选择哪种策略取决于对并发冲突频率和系统响应能力的权衡。
根据代码分析，选择**悲观锁**的原因如下：

## 1. 业务场景特点

ICDA 评估是**长时间运行的计算密集型任务**：
```java
private static final long SESSION_TIMEOUT = 600L; // 10分钟超时
```

10分钟的计算时间意味着冲突概率很高，如果用乐观锁会导致大量回滚。

## 2. 资源独占性

计算过程中独占大量内存和CPU资源：
```java
// IcdaContext 包含大量数据
private HistoryAssessmentSpIcdaDTO historyAssessmentSpIcdaDTO;
private List<SpIcDgMedIcAsmtOpDtDTO> spIcDgMedIcAsmtOpDtArrayList;
private Map<Double, Double> seriesMap;
```

多个并发计算会导致内存溢出或性能严重下降。

## 3. 业务语义要求

一个用户同时只能有**一个进行中的计算**：
```java
public boolean hasComputingSession(String userId) {
    Integer status = (Integer) redisService.getCacheObject(statusKey);
    return status != null && status == SessionStatus.COMPUTING.getCode();
}
```

这是业务硬约束，不是可并发的场景。

## 4. 乐观锁的痛点

如果用乐观锁（版本号机制）：
- 10分钟内的大量请求都会在**最后提交时失败**
- 用户体验差：点击"计算"后等很久才告知失败
- 浪费整个计算过程的资源

## 5. 悲观锁的优势

```java
public String tryAcquireLock(String userId, String sessionId) {
    // 检查锁是否存在且未过期
    if (existingLock != null && !isExpired(existingLock)) {
        return null; // 快速失败，立即告知用户
    }
    // 允许强制获取过期锁（程序崩溃恢复）
}
```

- **快速失败**：锁被占用时立即返回，用户无需等待
- **过期保护**：程序崩溃后锁自动过期，允许重新计算

---

**总结**：悲观锁适合"冲突频繁 + 冲突代价高 + 不适合并发"的场景。乐观锁适合"冲突稀少 + 回滚代价低"的场景。ICDA 计算10分钟独占资源，悲观锁是正确选择。

     * @return 锁令牌，如果获取失败返回null

    public String tryAcquireLock(String userId, String sessionId) {
        String lockKey = buildKey(userId, sessionId, "lock");
        String lockToken = UUID.randomUUID().toString().replace("-", "");

        // 检查锁是否已存在
        LockInfo existingLock = (LockInfo) redisService.getCacheObject(lockKey);
        if (existingLock != null) {
            // 检查锁是否已过期（防止程序崩溃后锁无法释放）
            if (System.currentTimeMillis() - existingLock.getCreateTime() < LOCK_EXPIRE_MILLIS) {
                log.warn("用户[{}]获取计算锁失败，sessionId={}，锁已被持有且未过期", userId, sessionId);
                return null; // 悲观锁：锁存在且未过期，返回失败
            }
            // 锁已过期，允许强制获取
            log.warn("用户[{}]获取计算锁发现过期锁，强制获取，sessionId={}", userId, sessionId);
        }

        // 设置锁
        LockInfo lockInfo = new LockInfo();
        lockInfo.setLockToken(lockToken);
        lockInfo.setCreateTime(System.currentTimeMillis());
        redisService.setCacheObject(lockKey, lockInfo, LOCK_EXPIRE_MILLIS / 1000, TimeUnit.SECONDS);
        log.info("用户[{}]获取计算锁成功，sessionId={}", userId, sessionId);
        return lockToken;
    }

        // 验证锁令牌
        if (lockToken != null && storedLock != null && lockToken.equals(storedLock.getLockToken())) {
            redisService.deleteObject(lockKey);
            log.info("用户[{}]释放计算锁成功，sessionId={}", userId, sessionId);
        }

package ceet.ufps.pl.pia.pia.session;

import ceet.ufps.common.redis.service.RedisService;
import ceet.ufps.pl.pia.api.dto.*;
import ceet.ufps.pl.pia.api.vo.AssessmentResult;
import lombok.Data;
import lombok.extern.slf4j.Slf4j;
import org.springframework.stereotype.Component;

import java.io.Serializable;

/**
 * ICDA评估会话状态管理器 - 乐观锁版本
 * 使用Redis的CAS(Compare-And-Swap)机制实现乐观锁
 *
 * @author wg
 */
@Slf4j
@Component
public class IcdaSessionManagerOptimistic {

    private static final String SESSION_PREFIX = "icda:session:";
    private static final long SESSION_TIMEOUT = 600L; // 10分钟超时

    @Resource
    private RedisService redisService;

    /**
     * 会话状态枚举
     */
    public enum SessionStatus {
        IDLE(0, "空闲"),
        COMPUTING(1, "计算中"),
        COMPLETED(2, "已完成"),
        FAILED(3, "计算失败");

        private final int code;
        private final String description;

        SessionStatus(int code, String description) {
            this.code = code;
            this.description = description;
        }

        public int getCode() {
            return code;
        }

        public String getDescription() {
            return description;
        }
    }

    /**
     * 带版本号的会话数据（用于乐观锁）
     */
    @Data
    public static class VersionedData<T> implements Serializable {
        private static final long serialVersionUID = 1L;
        private T data;
        private long version;

        public VersionedData() {}

        public VersionedData(T data, long version) {
            this.data = data;
            this.version = version;
        }
    }

    /**
     * 乐观锁结果
     */
    @Data
    public static class OptimisticLockResult<T> {
        private boolean success;
        private T data;
        private String message;

        public static <T> OptimisticLockResult<T> success(T data) {
            OptimisticLockResult<T> result = new OptimisticLockResult<>();
            result.setSuccess(true);
            result.setData(data);
            result.setMessage("操作成功");
            return result;
        }

        public static <T> OptimisticLockResult<T> conflict(String message) {
            OptimisticLockResult<T> result = new OptimisticLockResult<>();
            result.setSuccess(false);
            result.setMessage(message);
            return result;
        }

        public static <T> OptimisticLockResult<T> notFound() {
            OptimisticLockResult<T> result = new OptimisticLockResult<>();
            result.setSuccess(false);
            result.setMessage("数据不存在");
            return result;
        }
    }

    /**
     * 生成会话ID
     */
    public String generateSessionId() {
        return UUID.randomUUID().toString().replace("-", "");
    }

    /**
     * 获取或创建会话
     */
    public String getOrCreateSession(String userId) {
        String currentSessionKey = buildUserKey(userId, "currentSessionId");
        String sessionId = (String) redisService.getCacheObject(currentSessionKey);

        if (sessionId == null) {
            sessionId = generateSessionId();
            redisService.setCacheObject(currentSessionKey, sessionId, SESSION_TIMEOUT, TimeUnit.SECONDS);
            log.info("创建新会话 userId={}, sessionId={}", userId, sessionId);
        }

        return sessionId;
    }

    private String buildKey(String userId, String sessionId, String suffix) {
        return SESSION_PREFIX + userId + ":" + sessionId + ":" + suffix;
    }

    private String buildUserKey(String userId, String suffix) {
        return SESSION_PREFIX + userId + ":" + suffix;
    }

    /**
     * ========== 乐观锁核心方法 ==========
     */

    /**
     * 乐观锁更新会话状态
     * 返回更新后的状态，失败时包含最新版本号供重试
     *
     * @param userId    用户ID
     * @param sessionId 会话ID
     * @param newStatus 新状态
     * @param maxRetries 最大重试次数
     * @return 更新结果
     */
    public OptimisticLockResult<SessionStatus> updateStatusOptimistic(
            String userId, String sessionId, SessionStatus newStatus, int maxRetries) {

        String statusKey = buildKey(userId, sessionId, "status");
        String userStatusKey = buildUserKey(userId, "status");
        String currentSessionKey = buildUserKey(userId, "currentSessionId");

        for (int retry = 0; retry < maxRetries; retry++) {
            // 1. 读取当前版本
            VersionedData<Integer> versionedStatus = (VersionedData<Integer>) redisService.getCacheObject(statusKey);
            long currentVersion = (versionedStatus == null) ? 0 : versionedStatus.getVersion();

            // 2. 准备新数据
            VersionedData<Integer> newVersionedStatus = new VersionedData<>(newStatus.getCode(), currentVersion + 1);

            // 3. CAS更新（通过Lua脚本保证原子性）
            boolean updated = casUpdate(statusKey, versionedStatus, newVersionedStatus);

            if (updated) {
                // 更新用户维度的状态
                if (newStatus == SessionStatus.COMPUTING) {
                    redisService.setCacheObject(userStatusKey, newStatus.getCode(), SESSION_TIMEOUT, TimeUnit.SECONDS);
                    redisService.setCacheObject(currentSessionKey, sessionId, SESSION_TIMEOUT, TimeUnit.SECONDS);
                } else if (newStatus == SessionStatus.FAILED || newStatus == SessionStatus.IDLE) {
                    redisService.deleteObject(userStatusKey);
                }
                log.info("乐观锁更新状态成功 userId={}, sessionId={}, status={}, retry={}",
                        userId, sessionId, newStatus.getDescription(), retry);
                return OptimisticLockResult.success(newStatus);
            }

            // 4. 更新失败，获取最新版本重试
            log.warn("乐观锁冲突，准备重试 userId={}, sessionId={}, retry={}", userId, sessionId, retry);
        }

        log.error("乐观锁更新失败，已达最大重试次数 userId={}, sessionId={}", userId, sessionId);
        return OptimisticLockResult.conflict("状态更新失败，数据已被其他请求修改，请稍后重试");
    }

    /**
     * 乐观锁保存上下文
     *
     * @param maxRetries 最大重试次数
     */
    public OptimisticLockResult<IcdaContext> saveContextOptimistic(
            String userId, String sessionId, IcdaContext context, int maxRetries) {

        String contextKey = buildKey(userId, sessionId, "context");

        for (int retry = 0; retry < maxRetries; retry++) {
            // 1. 读取当前版本
            VersionedData<IcdaContext> current = (VersionedData<IcdaContext>) redisService.getCacheObject(contextKey);
            long currentVersion = (current == null) ? 0 : current.getVersion();

            // 2. 准备新数据
            VersionedData<IcdaContext> newVersioned = new VersionedData<>(context, currentVersion + 1);

            // 3. CAS更新
            boolean updated = casUpdate(contextKey, current, newVersioned);

            if (updated) {
                log.info("乐观锁保存上下文成功 userId={}, sessionId={}, version={}",
                        userId, sessionId, currentVersion + 1);
                return OptimisticLockResult.success(context);
            }

            log.warn("乐观锁冲突上下文，准备重试 userId={}, sessionId={}, retry={}", userId, sessionId, retry);
        }

        return OptimisticLockResult.conflict("上下文保存失败，数据已被修改");
    }

    /**
     * CAS更新核心方法
     * 使用Redis的WATCH+MULTI+EXEC实现乐观锁
     */
    private <T> boolean casUpdate(String key, VersionedData<T> oldValue, VersionedData<T> newValue) {
        // 方式1：使用Redis WATCH机制（推荐）
        // Spring Data Redis 的 RedisTemplate 支持 watch/unwatch/multi/exec
        // 此处需要注入 StringRedisTemplate 或 RedisTemplate

        // 方式2：使用Redis Lua脚本原子操作（更简洁）
        // 如果RedisService没有提供，可以自行实现

        // 这里假设redisService支持带条件的更新操作
        // 如果版本号匹配则更新，否则返回false
        return redisService.compareAndSet(key, oldValue, newValue, SESSION_TIMEOUT, TimeUnit.SECONDS);
    }

    /**
     * 检查并发冲突
     * 在执行业务操作前检查数据是否被修改
     */
    public boolean hasConflict(String userId, String sessionId, long expectedVersion) {
        String statusKey = buildKey(userId, sessionId, "status");
        VersionedData<Integer> current = (VersionedData<Integer>) redisService.getCacheObject(statusKey);

        if (current == null) {
            return expectedVersion != 0; // 期望0版本但数据不存在，算冲突
        }

        return current.getVersion() != expectedVersion;
    }

    /**

    public long getCurrentVersion(String userId, String sessionId) {
        String statusKey = buildKey(userId, sessionId, "status");
        VersionedData<Integer> current = (VersionedData<Integer>) redisService.getCacheObject(statusKey);

    }

## 核心对比

| 特性             | 悲观锁             | 乐观锁                   |
| ---------------- | ------------------ | ------------------------ |
| **冲突处理时机** | 获取锁时直接拒绝   | 提交时检测冲突           |
| **重试机制**     | 无需重试，快速失败 | 自动重试（CAS循环）      |
| **适用场景**     | 冲突频繁、代价高   | 冲突稀少、快速失败体验差 |
| **代码复杂度**   | 简单               | 稍复杂                   |
| **Redis Key**    | 独占的 `lock`      | 无需lock，用版本号代替   |

**关键点**：乐观锁的核心是 `VersionedData<T>` + `casUpdate()`，每次更新带上版本号，Redis 保证版本匹配才更新成功。
